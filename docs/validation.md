# 验证记录（更新至 v2.2.0）

验证日期：2026-10-08。环境：Debian 13 x86_64，Chrome 154.0.8037.57，Rust 1.95.0；发行内核静态链接 musl 与 libpcap 1.10.5。

## 代码审阅

在浏览器实测前审阅了参数输入、Chrome/CDP 生命周期、抓包线程、NetLog 归属、报文解码、TCP 重组、TLS record 解析、AnyTLS 规则和安装器。修复了重定向被误判为成功、进程组重复清理、截断重复计数、原始质量状态未保留、重组内存上限等问题，再进入实测。

实测发现 Chrome 154 的 TCP_CONNECT 结束事件使用 `local_address` / `remote_address`；已同时兼容旧字段。短突发流量在 libpcap immediate mode 下触发丢包，调整为 64 MiB 缓冲和 20ms 批量接收后测试零丢包。修复均加入了相应复核或回归测试。

## 验证范围

本机验证的是 Linux x86_64。其他发行版安装分支尚未逐一运行，aarch64 发行物未在本机验证。自然模式测试保留了协议协商，没有把 HTTP/2 回退宣称为 HTTP/3 成功。可选密钥已验证导出，内核本身不实现 TLS 解密。

本次未在用户的生产 AnyTLS 客户端/服务端部署候选配置。因此结果是有依据的实验性候选，而不是已验证的生产配置或流量伪装效果保证。

## v2.1.0：Comcast 页面失败修复

同一环境复现 `https://corporate.comcast.com/`：v2.0.1 默认无头原生 UA 收到 `net::ERR_HTTP2_PROTOCOL_ERROR`，NetLog 为 `Server reset stream.`，59 个包、2 条连接、0 次主页面成功，抓包无丢包。随机普通 Chrome UA 和有界面原生 UA 均获得主页面成功响应；仅禁用 HTTP/2 的对照仍失败。新内核显式使用 `--ua native` 再次复现该错误，终端和失败报告给出具体错误及桌面 UA 的重试建议。

默认策略改为 `--ua desktop`：在独立的 Chrome 内部页面读取本机真实 UA/平台/Client Hints，仅替换字符串中的 HeadlessChrome 标识。开发修复内核默认参数、20 秒公网实测得到 2 次主页面 HTTP 200（h2）、107 个请求、7850 个关联包、22 条连接，内核与网卡零丢包，满足实验性候选采样门槛。证书验证保持开启。

审阅覆盖 UA 探测目标关闭、原生模式保持原样、旧 session 反序列化兼容、页面加载状态与异步导航响应顺序、失败诊断及在线/离线质量门槛。页面加载结束前不再定时刷新，原有总时限仍有效。菜单明确默认选中无头、桌面 UA、TCP 三项。

通过 fmt、Clippy（零警告）、18 项 Rust 单元测试、10 项离线夹具测试及 18 项实际 Chrome 集成测试。新增测试包括默认 UA 被站点接受、原生 HeadlessChrome 被拒后仍正确返回失败、慢导航不被刷新中断、慢同步脚本可以执行完成。验证 HTTP UA、JavaScript UA、Client Hints 与浏览器读取值一致。完整回归中修正了测试工具跨轮积累干扰连接端口的误判：已释放的临时端口可能在后续轮次被复用，因此仅比较当前轮次的并发干扰连接。

正式内核使用 musl + libpcap 静态链接。网站行为、网络出口和后续浏览器版本可能变化，本次结果不扩大为所有站点可访问或生产 AnyTLS 配置已完成互通验证。

## v2.2.0：多轮分层采样、按位置规则与实际抓包筛选

默认三轮独立 Chrome 会话，总采样时长 60 秒，前两轮训练、最后一轮复核。每个采样轮、连接和发送位置分别保留证据；每轮最多 128 条连接，每条连接前 8 个加密记录及均匀抽取的后续记录；上下行分别统计。训练轮等权生成按位置变化的 P25–P75、P10–P90 区间，至少每轮 6 条合格连接。复核轮不参与生成规则，也不用于挑选训练第二名。

比对使用每轮六条分层代表序列驱动本机 AnyTLS 合成长度负载。默认基线及最多两组候选各重复两次，独立会话先同步配置；总计最多 180 条测试流（五轮模式）。回环中继仅标记测试写入窗口，Rust/libpcap 独立抓包、重组并核对完整上行加密记录序列，一致后才计算分布误差及 TLS/负载比。不将窗口标签冒充网站 Write 边界，也不将本机回环包长视为公网 TCP 分段。

Comcast 发布内核实测：3 × 20 秒，分别捕获 4344、5757、4803 个关联包，共 14904 包；用于分层采样的完整连接分别为 16、16、17。三轮质量检查通过。108 条实际 AnyTLS 测试流通过；默认配置复核分数 0.3232，按位置 P25–P75 候选为 0.1382，两次独立重复均通过改善、开销和耗时门槛。相同复核负载下，数据测试窗口上行 TLS 字节减少约 57.9%；该数值只对应本机长度驱动负载，不代表网页下载流量、生产节点或网络指纹相似性提升百分比。最终选中候选又通过新建/复用两种模式的 14 条完整性验证，临时节点清理完成。

审阅及测试中修正：

- SOCKS 成功响应可能早于 AnyTLS 隧道初始化，显式等待新隧道及初始化记录后才标记数据窗口，防止将握手/认证计入首个数据写入。
- 中继关闭 Nagle 延迟，并拒绝窗口之间出现未归属记录；pcap 记录序列与中继记录不一致时拒绝评分。
- 最初均分 256 MiB 总抓包额度使 Comcast 大资源在首轮触发上限，已保留每轮 256 MiB 的已有额度，并在菜单/文档公开多轮总量上限。
- 干扰连接即使在同一测试用例内也可能释放端口后被 Chrome 复用。测试夹具现在保留干扰套接字的重复描述符到用例结束，避免仅按端口集合产生误判；这不改变采集代码。
